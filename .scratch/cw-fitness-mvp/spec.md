# CwFitness MVP 产品规格

## 1. 产品目标

CwFitness 是一个面向个人日常健身记录的多用户 Web 应用。用户创建自己的每周训练计划，训练时快速记录每组实际结果，并在计划范围内查看按动作拆分的达成率与长期趋势。

MVP 首先验证训练现场记录是否足够快，其次验证按动作趋势和进阶提示是否能帮助用户看到进步。计划编辑只需灵活、可靠，不追求复杂周期化训练。

## 2. 成功标准

- 登录后最多 3 次主要操作即可开始一个建议训练。
- 达标的一组只需点击一次即可完成。
- 页面刷新后恢复到同一训练、同一组和同一计时状态。
- 主动挂起期间训练时间不增长。
- 短暂断网期间可以继续当前训练，恢复联网后不会重复写入。
- 完成训练后，动作趋势和每日训练时间立即更新。
- 1280px 桌面视口和 390px 手机视口均可完成全部核心流程。
- 所有关键流程可由键盘完成。
- 启用减少动态效果后，不出现位移动画。

## 3. MVP 范围

### 包含

- 邮箱与密码注册、邮箱验证、登录、退出和邮件找回密码。
- 每个用户的数据完全隔离。
- 全局自定义动作管理。
- 多个训练计划、计划内多个 Workout Day，以及建议星期。
- 逐组快速记录、挂起、继续、结束和放弃训练。
- 短暂断网草稿与恢复同步。
- 按计划隔离的动作达成率与趋势。
- 训练日历、历史列表、单次训练详情和每日训练时长。
- 只读的进阶提示。
- kg/lb 显示单位切换。
- 版本化 JSON 导入和导出。
- 最小化、可关闭且不含健身内容的遥测。
- 响应式、PC 优先的深色 tvOS 风格界面。

### 不包含

- 社交登录、好友、分享、排行榜或社交功能。
- 预置动作库。
- 动作参考视频、GIF 或用户上传媒体。
- 完整离线模式或 PWA 安装。
- 计划总达成率、跨计划动作汇总或综合健康分数。
- 卡路里、身体指标、RPE/RIR、备注、个人纪录徽章。
- 休息计时器、AI 教练、预测或自动修改计划。
- 复杂周期化、自动递进、训练待办实例或缺席率。
- 浅色主题。

## 4. 核心模型

领域术语以根目录 `CONTEXT.md` 为准。

- User 拥有自己的 Exercises、Workout Plans、Workout Sessions 和设置。
- Exercise 只定义稳定身份、最新名称、Resistance Type 和 Target Type，不包含组数或目标值。
- Resistance Type 为 `Weighted` 或 `Bodyweight`。
- Target Type 为 `Repetitions` 或 `Duration`。
- Planned Exercise 属于一个 Workout Day，定义统一重量、组数及每组次数或秒数。
- 一个 Workout Plan 包含多个可命名 Workout Day；每个 Workout Day 可有建议星期，但任意日期都能开始。
- Workout Session 是某个 Workout Day 在开始时生成的不可变目标快照。

## 5. 信息架构

### 主导航

- **Home**：今日建议、继续训练、最近训练、每日训练时间和进阶提示。
- **Plans**：训练计划与 Workout Day；全局动作管理作为计划编辑器中的二级入口。
- **Progress**：训练日历、历史训练、按动作趋势和训练时长。

设置位于头像菜单。训练过程使用独立的沉浸式页面。PC 使用悬浮侧栏或顶栏，手机使用三项底部导航。

### Settings

- 个人信息与用户时区。
- 重量单位。
- 遥测开关。
- JSON 导入与导出。
- 永久删除账户。

## 6. 账户与隐私

- MVP 对外开放邮箱和密码注册。
- 邮箱必须验证，并支持邮件找回密码。
- 密码哈希和 Session 交给成熟认证库处理；认证使用 Secure、HttpOnly、SameSite Cookie。
- 所有查询与写入必须按当前 User 授权，不能只依赖客户端传入的 userId。
- 用户时区注册时取浏览器值，之后可在设置中修改。
- 永久删除账户会级联删除用户拥有的计划、动作、训练、设置、草稿和遥测关联标识，并注销全部设备。
- 删除账户前提示用户先导出 JSON，并要求二次确认。

## 7. 动作管理

- 不提供预置动作库；用户自行创建动作。
- 创建时填写名称、Resistance Type 和 Target Type。
- 动作名称可修改，历史始终显示最新名称，稳定身份不变。
- 动作一旦被计划或历史使用，Resistance Type 和 Target Type 不可修改。
- Permanent Exercise Deletion 会从全部计划和 Completed Session 中删除该动作及其组结果、趋势和提示，但保留 Session 中其他动作。
- 若动作存在于任何 In-progress Session，永久删除被阻止。
- 删除前展示受影响的计划数、训练数和组记录数，并要求二次确认。

## 8. 计划编辑

- 每个用户可创建多个 Workout Plan，并为其设置名称、低饱和强调色和预置 `coverKey`。
- 每个计划包含多个可排序的 Workout Day。
- Workout Day 可命名、设置建议星期，并包含可排序的 Planned Exercise。
- 同一动作可用于多个计划；统计始终按计划隔离。
- Planned Exercise 的所有组使用相同目标，不支持逐组不同目标。
- `Weighted` 动作必须填写重量；`Bodyweight` 不要求重量。
- `Repetitions` 使用非负整数次数；`Duration` 使用非负整数秒。
- 重量输入非负、允许一位小数，可选择 kg 或 lb。
- 删除 Workout Day 或 Planned Exercise 只影响未来训练，历史 Session 快照保持不变。
- 计划可归档和恢复；归档后不能开始新训练，但历史仍可查看。
- MVP 不提供计划永久删除。
- 若已有 In-progress Session，计划编辑只影响以后新建的训练。

## 9. 开始训练

- User 全局最多有一个 In-progress Session。
- Home 优先展示正在进行的训练；存在时不能开始第二个。
- 没有进行中训练时，Home 展示今天建议的 Workout Day，同时允许选择任意计划中的任意 Workout Day。
- 开始时复制计划、训练日、动作顺序、目标组数、重量、次数/秒数、用户时区和本地日期，形成 Session 快照。
- 不支持手工补录、回填或修改训练日期。
- 允许训练自然跨午夜；统计归入开始时锁定的本地日期。

## 10. 训练记录

- 每组显示计划目标，但初始状态为未完成。
- 点击一次完成时，实际值采用计划值；用户可先修改实际值再完成。
- 实际次数和秒数为非负整数；实际重量为非负、最多一位小数。
- 空值或负数不能完成一组；`0` 在统计上等同跳过。
- 训练中不允许修改目标重量、目标次数/秒数或目标组数，也不能单独增删计划动作的组。
- 可移除整个动作，移除后该动作不参与本次统计；可跳过整个动作，所有目标组按零完成处理。
- 可追加一个新动作，但必须先填写完整目标；添加后目标锁定。
- 追加动作可选择保存到未来 Workout Day，默认开启；当前 Session 始终保留为 Added Exercise。
- Added Exercise 进入历史趋势，但只有成为 Planned Exercise 后，未来 Session 才开始累计进阶提示。
- 本次动作顺序可调整，但不写回未来计划。

## 11. 状态与训练时间

- Session 状态为 In-progress、Completed 或 Abandoned；In-progress 又分 active 与 paused。
- 点击“开始训练”进入 active 并开始累计 Training Time。
- 点击“挂起”后冻结组记录并停止计时；只允许继续或放弃。
- 点击“继续训练”开始新的 active 区间。
- 页面关闭不自动挂起。
- 客户端定期保存心跳；恢复时若距离最后心跳超过 5 分钟，未知区间视为挂起且不计时，用户确认后继续。
- Training Time 是所有 active 区间之和，不含 paused 或超时未知区间。
- 同一天多次 Completed Session 的 Training Time 可跨计划相加，形成每日训练时间。
- 有未完成组时点击结束，提示剩余数量；确认后把它们标记为 Skipped Set，再完成训练。
- 所有动作被移除且没有任何完成或明确跳过的组时，不能生成 Completed Session，只能继续或放弃。
- Abandoned Session 保留但不进入趋势和每日训练时间统计。

## 12. 多设备与同步

- PostgreSQL 后端是正式数据源。
- IndexedDB 仅保存当前训练草稿、待同步操作和必要的服务器版本，不保存独立权威副本。
- 短暂断网时可继续当前训练；恢复后按顺序提交 outbox，服务器成功确认后才删除本地操作。
- 每次写入包含 operationId 幂等键；重复提交不能生成重复组或重复状态变化。
- 可变实体保存版本号。版本冲突返回明确冲突，不执行 last-write-wins，也不静默覆盖。
- 计划冲突要求刷新后重新编辑，不做字段级合并。
- 同一 In-progress Session 同时只允许一个编辑设备。第二台设备可接管，接管后第一台设备变为只读并提示。
- 完整计划编辑与历史浏览在 MVP 中需要联网。

## 13. 达成率

### 单组得分

对每个目标组：

- `targetRatio = actualRepetitions / plannedRepetitions`，或 `actualSeconds / plannedSeconds`。
- `Weighted` 动作另算 `weightRatio = actualWeight / plannedWeight`。
- `Bodyweight` 组得分为 `min(targetRatio, 1)`。
- `Weighted` 组得分为 `min(targetRatio, weightRatio, 1)`。
- Skipped Set 的组得分为 `0`。

更高重量不能抵消次数或时长不足，更多次数或时长也不能抵消重量不足。

### 动作达成率

Exercise Achievement Rate 是该动作在 Session 中所有未移除目标组得分的算术平均值。最高为 100%。Added Exercise 使用它在添加时锁定的目标计算自己的达成率。

不计算计划总达成率，不跨动作或跨计划平均不同指标。

### 超额与进阶提示

- 当某组所有必需指标均达到目标，且至少一个指标超过目标时，该组存在 Exercise Excess。
- 同一计划内，同一 Planned Exercise 在目标完全相同的连续 3 次 Completed Session 中均达到 100%，且至少 2 次存在超额时，展示 Progression Suggestion。
- 计划目标的重量、组数、次数或时长任一改变，连续判断重新开始。
- `Weighted + Repetitions` 提示考虑增加重量。
- `Bodyweight + Repetitions` 提示考虑增加次数。
- `Bodyweight + Duration` 提示考虑增加时长。
- `Weighted + Duration` 提示考虑增加重量或时长。
- 提示不提供具体增量，不自动改计划，也没有应用或忽略按钮。
- 提示持续显示在 Home、计划详情和动作趋势页，直到对应 Planned Exercise 目标改变。
- 不发送邮件或浏览器通知，不使用阻塞式弹窗。

## 14. 历史与可视化

- Progress 训练日历按 Session 开始日标记 Completed Session，不使用计划达成率着色。
- 全局首页展示最近 4 周每日训练分钟柱状图及每周总分钟数。
- 计划页展示属于该计划的单次训练时长、完成训练次数和最近训练日期。
- 动作趋势默认展示最近 12 次包含该动作的 Completed Session。
- 趋势可切换最近 4 周、12 周和全部。
- 横轴使用 Session 开始日；同一天多次训练按完成时间排序。
- 每个动作分别展示重量、次数/时长和 Exercise Achievement Rate；不汇总不同动作的训练量。
- 同一动作在不同 Workout Plan 中分别统计，不提供跨计划总览。

## 15. 历史修正与删除

- Completed Session 允许修正每组实际重量、实际次数/秒数和 Skipped 状态。
- 修正后重新计算达成率、超额与进阶提示，并标注“已修改”。
- 不允许改变历史 Session 的动作、目标、日期、时间区间或计划归属。
- 整个 Completed Session 可永久删除，需二次确认。
- 删除计划结构不会删除历史；全局 Permanent Exercise Deletion 是唯一清除某动作历史组数据的入口。

## 16. 单位

- 用户可选择 kg 或 lb 作为显示和输入单位。
- 服务端内部保留统一、高精度的 kg 基准值。
- 切换单位只改变显示，不改写原值；用户主动编辑后才更新基准值。
- kg 与 lb 均显示一位小数，重复切换不能产生累计漂移。

## 17. JSON 导入与导出

- 导出当前 User 的完整计划、动作、训练和设置，包含 `schemaVersion`、`exportedAt` 与稳定 ID。
- 不包含密码、Session、遥测事件或任何媒体字段。
- 导入是账户级整体恢复，不支持合并。
- 导入前完整校验版本、结构、引用与数值；显示将被替换的数据摘要并二次确认。
- 恢复使用单个数据库事务；失败不得污染当前数据。
- 成功后其他设备的旧缓存失效并重新同步。

## 18. 遥测

- 默认只收集页面访问、功能操作类别、同步失败和去除敏感内容的错误信息。
- 不收集计划名、动作名、重量、次数、时长、训练日期或备注。
- Settings 提供关闭遥测的开关。
- 浏览器端不在 MVP 中部署实验性全量追踪；服务端使用结构化日志和必要错误诊断。

## 19. 视觉与交互系统

### 视觉方向

- 单一深色主题，不做浅色切换。
- 深色、低饱和健身摄影作为计划封面和 Home Hero。
- 每个计划选择一个低饱和强调色；动作不永久绑定颜色。
- 大画幅内容、克制留白、圆角横向卡片和一层清晰的半透明材质建立 tvOS 式层级。
- 不复制 Apple 商标、专有图标或 Activity Rings 的独特造型。
- 图片需有可追溯许可，下载进项目后生成 AVIF/WebP 响应式资源；不运行时热链。
- MVP 仅提供预置封面，数据库保存稳定 `coverKey`，JSON 不包含图片。

### 动效规则

- 按下时立即反馈，常用按钮使用约 `scale(0.97)` 的轻微压缩。
- 高频逐组记录不使用阻塞式入场动画；键盘操作不附加动画。
- 小型 UI 过渡通常保持在 300ms 内，进入使用强 ease-out，移动使用 ease-in-out。
- 拖动、抽屉和可逆交互从当前视觉状态继续，允许随时打断；动量手势才允许轻微回弹。
- 弹层从触发控件的空间位置产生；关闭时沿对称路径返回。
- 玻璃材质只用于浮动导航、工具栏或弹层，不在玻璃上重复叠玻璃。
- PC 指针景深和 hover 放大只在 `(hover: hover) and (pointer: fine)` 启用。
- 手机取消指针视差，以轻触反馈和共享元素过渡替代；任何功能都不能只靠 hover。
- 只动画 `transform` 与 `opacity` 等合成友好属性；大背景不做持续运动。
- `prefers-reduced-motion` 使用短交叉淡化替代位移、视差和弹簧。
- `prefers-reduced-transparency` 使用更实的深色表面；`prefers-contrast` 提高边界与文字对比。

## 20. 技术基线

- Next.js App Router + TypeScript。
- PostgreSQL + Prisma 7，并提交可审查的数据库迁移。
- Better Auth 提供邮箱密码、验证、找回密码和数据库 Session。
- Dexie 管理 IndexedDB 训练草稿和 outbox。
- Recharts 绘制趋势与时长图表。
- Motion 仅用于动态、可中断的手势或共享元素；确定性高频反馈优先 CSS/WAAPI。
- Vitest + Testing Library 覆盖领域逻辑、同步状态机和组件。
- Playwright 覆盖登录、计划、训练、刷新恢复、断网同步、单位切换、删除和响应式关键流程。
- Docker 部署单个应用实例并连接独立 PostgreSQL；反向代理负责 HTTPS、限流和请求体限制。
- 数据库迁移作为独立发布步骤执行，不能由多个应用副本并发运行。

## 21. 测试与验证

### 领域单元测试

- 四种 Resistance Type × Target Type 组合的组得分。
- 低重量与高次数不能互相补偿。
- Skipped Set、Removed Exercise、Added Exercise 和达成率上限。
- 进阶提示的连续三次、两次超额、目标变化重置和四种提示方向。
- kg/lb 往返显示不导致基准值漂移。
- Training Time 排除挂起与超过 5 分钟的未知区间。
- 跨午夜归属开始日。

### 集成测试

- 用户数据隔离和所有资源的服务端授权。
- Session 快照不受后续计划修改影响。
- 幂等 operationId 不产生重复写入。
- 版本冲突拒绝静默覆盖。
- JSON 导入事务失败时完整回滚。
- Permanent Exercise Deletion 的级联范围与进行中阻止规则。
- User Deletion 清除范围和全设备会话失效。

### 端到端测试

- 注册、验证、登录、找回密码和退出。
- 创建动作、计划、Workout Day，并开始建议训练。
- 一键完成组、修改实际值、跳过、移除和追加动作。
- 挂起/继续、刷新恢复、异常心跳恢复和完成训练。
- 离线记录、恢复同步、多设备接管与旧设备只读。
- 历史修正、Session 删除、动作永久删除和账户删除。
- 390px 手机与 1280px 桌面关键路径。
- Chromium 全量关键路径；Firefox 与 WebKit 覆盖登录、训练和图表主流程。
- 键盘导航、焦点可见性、减少动态、减少透明度和高对比度降级。

## 22. 后续版本候选

- PWA 与完整离线浏览/编辑。
- 休息计时器、RPE/RIR、备注、身体指标和个人纪录。
- 逐组不同目标与更复杂的周期计划。
- 社交、计划分享、跨计划分析和开放注册管理工具。
- 用户上传封面或动作参考媒体。
- 包含媒体的 ZIP 备份。
- 更精细的多设备协同编辑与冲突合并。
